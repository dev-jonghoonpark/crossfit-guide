# 포즈 검사 스크립트

포즈를 고친 뒤 **애니메이션 중간 프레임**에 문제가 없는지 재는 도구다.
키프레임만 눈으로 봐서는 안 보이는 것들이라 손으로는 못 잡는다.

```bash
node tools/pose-check/bar-clearance.mjs bar-muscle-up   # 몸이 봉을 뚫고 지나가는가
node tools/pose-check/limb-fold.mjs                     # 팔·다리가 비정상적으로 접히는가
node tools/pose-check/fold-direction.mjs                # 팔꿈치·무릎이 반대로 꺾이며 도는가
node tools/pose-check/stance.mjs                        # 사람이 취할 수 있는 자세인가
```

## bar-clearance — 봉 관통

철봉을 쓰는 동작에서, 두 키프레임 사이를 21 프레임으로 쪼개 몸통·다리 뼈가
봉(원)과 겹치는지 잰다. 손과 아래팔은 봉을 잡고 있으니 뺀다.
동작 id 를 인자로 주면 그 동작만 본다(기본값은 바 뮤스클업).

바 뮤스클업은 몸이 봉을 한 바퀴 돌아 넘어가는 유일한 동작이라, 가슴이 봉을
스치는 1 프레임만 남는 게 정상이다(그 순간은 실제로 봉이 몸에 닿는다).
그보다 많이 나오면 `data/poses.js` 의 BMU 주석에 적힌 세 가지 규칙을 확인한다.

풀업은 정점에서 `neck-shoulder` 가 걸리는데 이건 정상이다 — 턱이 봉을 넘은
자세라 봉이 턱·목 높이에 있는 게 맞다. 그 외 뼈가 걸리면 실제 문제다.

## limb-fold — 비정상 접힘

두 포즈 사이에서 팔꿈치·무릎이 접히는 **방향**이 뒤집히면, 보간이 "완전히
접힌 상태"를 지나가면서 손이 어깨에, 발이 골반에 닿는 가짜 자세가 만들어진다.
각 구간의 중간 프레임이 양 끝 키프레임보다 8 이상 더 접히면 잡아낸다.
0 이 아니면 그 구간의 팔꿈치·무릎 위치를 다시 봐야 한다.

## fold-direction — 접히는 방향

팔꿈치·무릎이 두 포즈 사이에서 접히는 **방향**이 뒤집히면, 보간기는 "쫙 편
상태(0°)"가 아니라 "완전히 접힌 상태(±180°)"를 지나 도는 쪽을 짧은 길로
고를 수 있다. 그러면 중간 프레임에서 손이 어깨에 닿을 만큼 팔이 접히고,
손이 봉에 고정돼 있으니 몸 전체가 끌려가 봉 위로 튀어 오른다.

각 구간의 굽힘 각을 재서 0° 를 지나지 않는 구간을 잡아낸다.
동작 id 를 주면 그 동작만, 안 주면 전 동작을 본다.

**바 뮤스클업의 하이 풀 → 트랜지션 1건은 정상이다.** 손이 어깨 위에서 아래로
뒤집히는 구간이라 방향이 바뀔 수밖에 없고, 대신 위팔·아래팔을 다르게 그려
(22 / 39) 아무리 접혀도 손이 어깨에 닿지 못하게 막아 뒀다.
그 외에 잡히면 두 포즈 중 하나의 팔꿈치·무릎을 선 반대쪽으로 옮긴다 —
거의 편 상태라면 그림은 그대로고 보간만 고쳐진다.

## stance — 자세가 성립하는가

앞의 셋은 애니메이션(구간 사이)을 보지만, 이건 **정지 화면 하나**만 봐도 알 수 있는
것들이다. 포즈를 새로 만들면 제일 먼저 돌린다.

- **무릎 꺾임 방향** — 사람 무릎은 앞으로 꺾이지 않는다. 허벅지 대비 정강이 각이
  음수면 잡아낸다(거의 편 다리는 부호가 오차 수준이라 -8° 부터 본다).
- **균형** — 두 발로만 서 있는 자세에서 무게중심이 뒤꿈치~발끝 밖으로 나가면
  그 자세로는 넘어진다. 바를 들었으면 체중의 0.8배로 같이 계산한다.
  벤치·로잉 머신에 앉거나 손이 바닥에 닿은 자세는 지지면이 발이 아니라 건너뛴다.

무게중심이 발 안에 있어도 다리가 거의 펴진 채 크게 기울어 있으면 어색해 보인다.
힌지 자세의 무릎 꺾임각은 기존 포즈를 기준으로 삼자 — 데드리프트 셋업 66° ·
행 포지션 35° · 펜들레이 로우 30° 정도다.
